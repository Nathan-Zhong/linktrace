# 循迹 Linktrace · 阶段 B 保险库设计（草案）

版本：v0.1 草案　日期：2026-11-24　依据：《Linktrace_P0_PRD.md》v1.0、阶段 A 威胁模型

**本文件是设计草案，不是实现、不是安全证明。** 全部参数须经真机标定与独立审查确认后才可实施；全部 GATE 均未通过。

## 1. 数据分域

现有关系域（上游已实现，三端同构 JSON，`AtlasData`）保持不动：

- `Identity`（邮箱/手机号/QQ/微信/Apple ID/自定义）、`Account`（平台账号）、关联关系、分类、标签、分组、普通备注。

新增保险库域（P0 新建，与关系域物理分开存放、分开加密、分开同步许可）：

| 实体 | 内容 | 同步 | 备份 |
|---|---|---|---|
| `VaultCredential` | 账号 id、用户名、密码密文、创建时间、更新时间、密钥版本 | 永不 | 随加密备份 |
| `PasswordHistory` | 旧密码密文 + 替换时间，按保留策略 0/5/10/全部 | 永不 | 随加密备份 |
| `RecycleBinItem` | 已删凭据密文 + 删除时间，保留 7/30/90 天或关闭（默认 30 天） | 永不 | 随加密备份 |
| `SensitiveField` | 自定义敏感字段密文（标记为敏感的备注/字段） | 永不 | 随加密备份 |
| `VaultMeta` | 密钥版本、KDF 参数、盐、封装后的数据密钥、创建时间 | 永不（本机） | 不进备份文件（备份用独立备份密码重新封装，见 §3） |

关系域与保险库域的关联只用账号 id；保险库记录中不出现邮箱、手机号等身份明文（避免保险库文件本身成为身份清单）。

## 2. 密钥层级

```
主密码 ──Argon2id(盐随机, 参数待标定)──► KEK（密钥封装密钥，仅内存）
KEK ──封装──► VDK（随机 256 位保险库数据密钥，唯一长期密钥材料）
VDK ──AES-256-GCM──► 全部保险库记录（每条记录独立随机 96 位 nonce + 认证标签 + 密钥版本）
```

- **主密码**：不明文保存、不存可逆形式；只用于派生 KEK；输错即解密失败，不提示“接近正确”。
- **VDK**：建库时用系统安全随机源生成；以封装后形态落盘；轮换时生成新 VDK 并重加密全部记录，旧版本标记作废，轮换须经用户确认并在断电/崩溃后可恢复到旧版本（先写新、再切版本、最后清旧）。
- **生物识别快捷解锁**：生物识别只解开已封装的密钥材料（经 Keystore/Keychain 保护的封装密钥），不绕过主密码权限边界；生物识别配置变化（新增/删除指纹或面容）或密钥失效时，封装密钥作废，回退主密码。
- **禁止**：硬编码密钥、固定 IV/nonce、Base64/混淆代加密、自创算法、把网站密码只做哈希（须可解密填充）。

## 3. 平台密钥保护

| 平台 | 密钥材料存放 | 备注 |
|---|---|---|
| Android | Android Keystore（可用设备上硬件支持，StrongBox 优先于 TEE，须检测并记录实际等级） | KEK/VDK 封装密钥进 Keystore；保险库文件放应用私有目录，`allowBackup=false` 已有关闭自动备份，仍须按版本验证排除策略 |
| iOS | Keychain，`kSecAttrAccessibleWhenUnlockedThisDeviceOnly` 类属性；能用 Secure Enclave 的密钥操作优先 | 保险库文件放应用沙箱，不进 iCloud 备份；Keychain 项须验证备份/迁移行为 |
| 网页版 | 不做保险库 | 关系数据可用 LocalStorage；密码保险库禁入普通 Web LocalStorage |

## 4. 加密备份（唯一允许跨设备移动秘密的路径）

- 用户主动导出才产生备份文件；默认不产生明文备份。
- 备份文件格式（版本化信封）：`{v, kdf, salt, iv, ct, at}`；独立备份密码经 Argon2id 派生备份密钥，AES-256-GCM 加密整个备份载荷（含 VDK 的重新封装形态 + 全部保险库记录 + 关系数据快照）。
- 导入时：先解密校验认证标签，错误密码或破损文件**不产生部分覆盖**（先解到临时区、校验通过后再原子替换）；导入前提示先备份当前数据，支持回滚。
- 备份密码遗失或文件损坏即不可恢复，导出与导入界面须显著说明。

## 5. 锁定与使用规则

- 后台约 1 分钟锁定；设备锁屏立即锁定；后台预览始终遮罩。
- 查看密码、复制密码、每次自动填充：单独重新验证身份（生物识别或主密码）。
- 复制到剪贴板后尽可能 30 秒清除，只在剪贴板仍为该密码时操作，不覆盖用户后来复制的内容；系统限制下不承诺完全可靠。
- 机密仅必要时短暂驻留内存并及时清理；不写入日志、通知、搜索索引、最近任务缩略图。

## 6. 待定参数与待评估项（须真机标定 + 独立审查）

1. **Argon2id 参数**（内存、迭代次数、并行度）：须在目标设备（低端 Android 与 iOS）上标定解锁耗时目标（建议：交互解锁 ≤ 1 秒量级，具体数值待测后定），参数与 KDF 库选择须经独立审查。
2. **Argon2id 实现选型**：Android 与 iOS 均无系统内置 Argon2id，须评估广泛审查的第三方实现（候选须逐一核查维护状态、审计记录与供应链）；若无合适实现，PRD 允许的等价方案是经审查的高强度 PBKDF2-HMAC-SHA256（须同步提高迭代次数并记录决策依据）。**未审查确认前不写实现代码。**
3. **AES-GCM 实现**：Android 用平台 `Cipher AES/GCM/NoPadding`；iOS 用 CryptoKit AES-GCM；均须单元测试覆盖。
4. **密钥轮换与恢复流程**：主密码修改、生物识别失效、设备迁移、备份恢复四条路径的测试用例，见验收矩阵 AC-02/AC-03/AC-09。
5. **存储形态**：保险库记录以加密文件 + 加密索引存放，还是加密数据库，待实现时按“可审计、可原子替换、可彻底删除”三条选；删除须覆盖当前数据、历史、回收站、缓存与导出临时文件。

## 7. 测试要求（实现后逐项取证）

- 加密往返：随机 nonce 每次不同、篡改密文认证失败、错主密码解密失败。
- KDF：同口令不同盐结果不同、参数变更后旧数据可迁移。
- 锁定：后台超时、锁屏、进程切换的锁定与状态清理。
- 备份：导出→新设备导入恢复、错密码零写入、破损文件零写入。
- 负面测试：抓包与日志中无明文/可恢复秘密；同步载荷不含任何秘密字段（自动化回归测试，GATE-05）。
