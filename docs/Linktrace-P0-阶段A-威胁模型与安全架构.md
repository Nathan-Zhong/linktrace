# 循迹 Linktrace · 阶段 A 威胁模型与安全架构（草案）

版本：v0.1 草案　日期：2026-11-24　依据：《Linktrace_P0_PRD.md》v1.0

**本文件是设计草案，不是安全证明。** 它只说明“打算怎么防”，不证明“已经防住”。全部 GATE 均未通过，独立审查尚未进行，上游仓库盘点因基线确认未完成而待补。任何基于本文件的发布宣称都是不实的。

## 1. 范围与假设

- 产品：本地优先的数字身份、平台账号与密码管理器；Android 原生（Kotlin / Jetpack Compose）、iOS 原生（SwiftUI + 系统凭据扩展）。网页版保留已有账号关系能力，**密码保险库不得放入普通 Web LocalStorage**（未经独立安全设计）。
- 责任边界（PRD §01）：应用对自身加密、密钥保护、数据存储、同步、自动填充匹配、隐私显示、日志、备份与分发流程中的缺陷负责；不承诺对遭攻陷设备、用户自主泄露、目标网站被盗、恶意软件等第三方事件做到“零风险”。绝不宣称 100% 不会泄露。
- 假设攻击者能力：可读取应用发出的网络流量；可拿到用户导出的文件、旧备份、崩溃报告；可构造钓鱼域名与仿冒 App；可读取设备系统备份（若保险库被错误地纳入备份）；**不可假设攻击者拿不到这些东西**。不假设设备已被攻陷（已攻陷设备超出本应用可控制范围，须如实披露而非宣称能防）。
- 禁止的手段（硬性）：无障碍监控、屏幕抓取、后台键盘记录、跨应用私有目录扫描、越权获取其他 App 登录凭据、为提高填充成功率降低身份校验。

## 2. 资产清单

| 资产 | 敏感度 | 说明 |
|---|---|---|
| 网站/平台密码、历史密码、回收站密码 | 最高 | 可直接登录用户账号；须可解密（为填充），禁只做哈希 |
| 主密码 | 最高 | 解锁保险库的根口令；不明文保存，不进任何同步/日志/上报 |
| 保险库数据密钥（随机 vault data key） | 最高 | 真正加密数据的密钥；须被主密码派生密钥封装，禁硬编码、禁明文落盘 |
| 备份密码 / 备份文件 | 最高 | 唯一允许跨设备移动秘密的路径；密码遗失或文件损坏即不可恢复，须显著告知 |
| 敏感自定义字段、敏感备注 | 高 | 与密码同等保护，只在本地保险库 |
| 登录令牌（OAuth 等） | 高 | P0 不保存第三方登录令牌；只记录关系 |
| 身份信息：邮箱、手机号、QQ/微信标识、用户名、账号关系图 | 高 | 可关联个人身份；按同步许可分域处理 |
| 同步令牌（Gitee/GitHub gist token） | 高 | 只存本机受保护存储；泄露可导致关系数据被读/写，禁入日志与仓库 |
| 普通备注、分类、标签、分组 | 中 | 可参加用户主动开启的关系同步，但同步前提醒可能含敏感信息 |

## 3. 信任边界与数据流

```
用户 ──(生物识别/主密码)──► 保险库解锁 ──► 内存中短暂解密 ──► 填充/查看/复制
  │                              │                    │
  │                              ▼                    ▼
  │                     Android Keystore / iOS Keychain（含 Secure Enclave 优先）
  │                              │
  ├─ 账号关系同步（默认关闭，用户主动开启）──► 端到端加密载荷 ──► 用户自己的 Gitee / GitHub 私密 Gist
  ├─ 加密备份（用户主动导出/导入）──► 独立备份密码加密的文件 ──► 用户自选位置
  ├─ 系统自动填充 ──► 官方 Autofill / Credential Manager（Android）、Credential Provider Extension（iOS）
  └─ 系统备份/迁移 ──► 保险库数据必须被排除（Android 备份排除配置；iOS Keychain 仅本机属性）
```

边界规则：

- **秘密永不过“关系同步”边界。** 密码、历史、敏感字段、回收站、保险库密钥绝不进入同步载荷、设备云备份、崩溃上报、网络日志、外部图片/字体请求。
- **秘密永不进 Web。** 网页版只有账号关系能力；密码保险库不进普通 Web LocalStorage。
- **填充是单向窄门。** 凭据只在“可信身份已匹配 + 用户已选账号 + 本次已验证 + 交付前来源未变”四条件同时满足时才交出；任一条件失败即拒绝，不猜测。
- **日志/崩溃/遥测边界默认关闭。** 默认不接广告、行为分析、未审查崩溃上报 SDK；任何诊断信息禁含秘密。

## 4. 威胁清单（映射到 PRD 安全要求）

| # | 威胁 | 攻击面 | 对应 | 缓解设计（须经测试与独立复核验证） |
|---|---|---|---|---|
| T1 | 密码明文落盘（数据库/文件/SharedPreferences/缓存） | 本地存储 | SEC-01 | 全部秘密字段 AES-256-GCM 加密后落盘；密钥版本化；自动化回归测试扫描落盘内容 |
| T2 | 主密码被猜/被逆向（弱 KDF、固定盐、硬编码密钥） | 密钥派生 | SEC-01 | Argon2id（参数按目标设备标定，须独立审查确认）；随机盐；随机保险库数据密钥 + 密钥封装；禁自创算法 |
| T3 | 密钥从 Keystore/Keychain 被绕过（生物识别降级、配置变更） | 系统密钥存储 | SEC-01 | 生物识别与主密码走同一权限边界；生物识别配置变化/密钥失效安全回退主密码；Android 硬件支持优先，iOS Secure Enclave 优先 |
| T4 | 关系同步带走秘密 | 云同步 | SEC-02 | 数据分域（见 §5）；同步载荷白名单制，只含准许字段；自动化测试断言同步载荷不含秘密字段 |
| T5 | 系统云备份带走保险库 | 系统备份 | SEC-03 | Android 自动备份/迁移排除配置并覆盖不同版本；iOS 仅本机 Keychain 属性；真实备份/恢复/卸载重装测试（AC-13） |
| T6 | 钓鱼网站/App 骗取填充 | 自动填充匹配 | SEC-04 | 严格可信匹配：网站 host 与安全上下文、Android 应用身份/签名 + Digital Asset Links、Apple 关联域；交付前二次校验防 TOCTOU；相似域名、HTTP、伪造包名、恶意 WebView 一律拒绝 |
| T7 | 填充来源在验证后被调换 | TOCTOU | SEC-04 | 交付凭据前再次确认请求身份未改变；改变即拒绝 |
| T8 | 越权获取密码（无障碍/键盘记录/截屏/目录扫描） | 权限滥用 | SEC-04 | 禁用全部越权手段；只用官方 Autofill / Credential Manager / Credential Provider API；最小权限；不支持场景明示拒绝 |
| T9 | 锁屏/后台泄露（最近任务缩略图、后台预览、剪贴板历史、通知） | 生命周期/屏幕 | SEC-05 | 锁屏立即锁定；后台约 1 分钟锁定；后台预览始终遮罩；机密短暂驻留内存并及时清理；剪贴板 30 秒清除（只清仍为该密码时，不承诺绝对可靠）；iOS 截屏限制如实告知 |
| T10 | 日志/崩溃报告带走秘密 | 可观测性 | SEC-02/05 | 日志脱敏审查；秘密字段禁入日志、崩溃上报、搜索索引、通知；抓包测试（AC-07） |
| T11 | 明文 CSV 导入残留（文件、日志、部分写入） | 导入/迁移 | F06 | 明文 CSV 只本地解析；预览 + 映射 + 冲突由用户定；事务/快照回滚；完成后提醒清理原始文件；CSV 不进同步与日志 |
| T12 | 备份文件被破解/损坏导致不可恢复或部分覆盖 | 备份/恢复 | F06 | 独立备份密码加密；错误密码或破损文件不产生部分覆盖；遗失不可恢复须显著告知 |
| T13 | 依赖/供应链带入漏洞或秘密 | 供应链 | SEC-06 | 依赖锁定版本；SCA/SBOM 与漏洞扫描；优先广泛审查的加密库；源码与 CI 秘密扫描；独立签名密钥与最小权限 CI |
| T14 | 第三方图标/字体/域名请求暴露用户使用的平台 | 网络隐私 | SEC-02 | 图标等资源尽量离线；联网加载须单独告知并获同意；绝不把整份账号清单传给第三方 |
| T15 | 弱密码/重复密码被上传分析 | 安全中心 | F05 | 弱密码与重复检测只本地计算；不上传密码或可逆向识别的稳定派生值；结果仅提示，不宣称检测真实泄露 |
| T16 | 删除不彻底（历史/回收站/缓存/导出临时文件残留） | 删除 | SEC-05 | 删除覆盖当前数据、历史、回收站、缓存与导出临时文件；不宣称“绝对物理擦除” |

## 5. 数据分域与同步边界矩阵

| 数据类别 | 例子 | 本地存储 | 可进关系同步？ | 同步形式 | 可进加密备份？ |
|---|---|---|---|---|---|
| 秘密 | 网站密码、历史密码、回收站密码、敏感字段、保险库密钥 | AES-256-GCM 加密 | **否，永不** | — | 是（备份密码加密） |
| 身份与关系 | 邮箱/手机号/QQ/微信/Apple ID、平台账号、关联关系、分类、标签、分组、普通备注 | 关系数据本地存储；敏感部分按秘密处理 | **仅用户主动开启时**，白名单字段 | 端到端认证加密，密钥只在用户设备/口令掌控 | 是（与秘密同等加密） |
| 元数据 | 时间戳、最近使用排序、变更历史（旧邮箱手机号按个人信息保护） | 本地 | 随关系数据（须脱敏审查） | 同上 | 是 |
| 同步凭证 | Gist token、同步配置 | 系统受保护存储（Keystore/Keychain） | 否 | — | 否（新设备重新授权） |

同步默认关闭。开启前须提醒：普通备注可能包含敏感信息。

## 6. 加密方案草案（须独立审查确认后才可实施）

- **保险库数据密钥**：每次建库生成随机 256 位数据密钥；全部秘密字段用该密钥以 AES-256-GCM 加密，每次加密独立随机 96 位 nonce、附认证标签、记录密钥版本。禁固定 IV、禁 nonce 重用、禁 Base64/混淆代加密。
- **密钥封装**：主密码经 Argon2id（参数按目标设备标定：内存、迭代、并行度须在真机上测出并经审查确认）派生密钥封装密钥（KEK），KEK 封装随机数据密钥。主密码本身不明文保存、不存可逆形式。
- **生物识别快捷解锁**：生物识别只解开已封装的密钥材料，不绕过主密码权限边界；生物识别配置变化或密钥失效时回退主密码。
- **平台密钥保护**：Android 用 Android Keystore（可用设备上硬件支持）；iOS 用 Keychain（合适访问控制，`ThisDeviceOnly` 类属性）并优先 Secure Enclave 密钥操作。
- **加密备份**：独立备份密码经 Argon2id 派生备份密钥，AES-256-GCM 加密整个备份文件；错误密码或破损文件不得部分覆盖现有数据。
- **关系同步加密**：沿用原项目已验证的端到端加密信封思路（PBKDF2-HMAC-SHA256 31 万次 → AES-GCM，密文 `{v,salt,iv,ct,at}` 存私密 Gist），但**须重新审查确认参数与实现**，且同步载荷只含白名单关系字段。原项目的同步只覆盖关系数据，密码从不同步——这一边界在 Linktrace 中保持不变。
- **明确不做的事**：不自创加密算法；不把网站密码只做哈希（须可解密填充）；不把保险库放进 Web LocalStorage；不承诺剪贴板清除与 iOS 截屏阻止超出系统能力。
